**System calls used in this project**

**getpidd() & getppid()**

		pid_t	getpid();
		pid_t	getppid();

	getpid() - returns the process ID of the calling process. 
		The ID is guaranteed to be unique and is useful for constructing temporary file names

	getppid() - returns the process ID of the parent of the calling process.

	pid_t - return value usually int or long, depends on the system

	libraries:
		#include <sys/types.h>
		#include <unistd.h>

	Errors
		The getpid() and getppid() functions are always successfull, and no return value is reserved to indicate an error.

**fork()**

		pid_t	fork(void);

	fork() creates a new process by duplicating the calling process. The new process is referred to as
	the CHILD process. The calling process is referred to as the PARENT process.

	RETURN VALUE
		On success, the PID of the CHILD process is returned in the parent, and 0 is returned in the child.
		On failure, -1 is returned in the parent, no child process is created, and errno is set appropriately.

	So in case of success system call fork():
		Parent process will get child's PID
		Child process will get 0

	So this system call fork() return at the same time two values, for parent and for child

**wait()**

	wait, waitpid, waitid - wait for process to change status

	#include <sys/wait.h>

	pid_t	wait(int *wstatus);
	pid_t	waitpid(pid_t pid, int *wstatus, int options);

	RETURN VALUE
	wait return -1 in case of error

	Explanation

	For PARENT process to get information how it's child process was ended/finished, parent process need to use function wait()

	Function wait stops parent process until the status of some of childs won't change

	Wait returns pid of changed process, and information about it's status stored in variable "wstatus"

	Process could be stopped by different reasons:
	- exit()
	- return()
	- SIGKILL
	All the codes with that process ends are encrypted to variable wstatus with information about ended process

	Macros to return wstatus - WIFEXITED - returns true if the child terminated normally, that is, 
		by calling exit(3) or _exit(2), or by returning from main().

**_access_**

	int	access(const char *pathname, int mode);

		pathname - pointer to string with full path to the file (for instance /bin/cat)

**redirection**

	< - input redirection - describes that command should read not from stdin
		syntax: command < filename
			
			grep "pattern" < file1

			Shell opens file1 in O_RDONLY mode and file's descriptors double to STDIN_FILENO with dup2
			Command get's input like from user input

	> - output redirection - redirects stdout to specified file, rewriting it's content
		syntax: command > output.txt

			Shell opens filename in writing mode (O_WRONLY | O_CREAT | O_TRUNC) with rights usually 0644 or 0777
			Descriptor dubbles to STDOUT_FILENO
	
	>> - append output redirection - redirects stdout to file, addinf data to the end of 
			currentdata in the file

			syntax: command >> filename

			echo "new line" >> output.txt - new string will be added to the end of the file

			shell opes file in appending mode (O_WRONLY | O_CREAT | O_APPEND)

	<< - here_doc (Input from Inline Data)

			<< is used to create here_doc - mechanism, that allows to move data to command through strin until specified delimeter. Used for multiline input

			syntax: command << delimeter

			wc -l << EOF line1 line2 EOF
				command wc -l will calculate strings line1 and line2, result - 2

			cat << DELIMITER >> output.txt 
			
			Shell reads strings from terminal or script until string, that equals delimeter (usually on the sepparate line)
			This lines moves to command like stdin
			After delimeter input stops

			If argv[1] == "here_doc", then argv[2] - delimeter
			New temporary file is created, where data from stdin written until delimeter(with get_next_line)
			After fd_in = open (temporary_file, O_RDONLY) and process goes as < file1
			Afterall temporary file is deleted with unlink

		<< is spaces ' ' sensitive if it's not specified differently, <<- ignores tabs

** wait() **

	Library:
		
		#include <sys/wait.h>

	Syntax:
	
		pid_t	wait(int *wstatus);

	Returns child's PID, if error returns -1;

	it's a key to synchronisation of the processes in pipex.

	Parent should wait for child processes in case not to create zombi processes from childs.

	wait() is basic function, but in pipex more useful waitpid().

	waitpid

	syntax:

	pid_t waitpid(pid_t pid, int *wstatus, int options);

	options:

	- 0 == block (by default)
	- WNOHANG == not to block (check if it's done)
	- WUNTRACED == wait till ends(debug)

	for pipex we use waitpid(pid, &wstatus, 0);


** wstatus **

	wstatus its an int, to where waitpid is writing status after command is finished. It's a bit mask

	WIFEXITED(wstatus)   -> Was It Finished EXITED   -> returns 1/0 -> 1 if return/exit()

	WEXITSTATUS(wstatus) -> What EXIT STATUS         -> returns int -> code from return N (0-255)

	WIFSIGNALED(wstatus) -> Was It Finished SIGNALED -> returns 1/0 -> 1 if it was killed by signal

	WTERMSIG(wstatus)    -> What TERM SIGNAL         -> returns int -> # of signal (9=SIGKILL)

	WIFSTOPPED(wstatus)  -> Was It Finished STOPPED  -> returns 1/0 -> 1 if stopped(debug)

	WSTOPSIG(wstatus)    -> What STOP SIGNAL         -> returns int -> # of stop signal


** exec() **

	execute - Process image replacement. 

	exec() - executing command inside of current process without changing PID

	exec - basic name with possible args:

		l - list : arguments passed as list of paramenters (varargs: arg0, arg1, arg2 ... , NULL)

		v - vector : arguments passed as array (char const *argv[])

		p - path : fucntion looks for programm in environment variable PATH (e.g. /bin:/usr/bin)

		e - environment : additiopnally passes array of environment (char * const envp[])

		examples:

		execl = exec + list

		execvp = exec + vector + path - perfect for pipex, we're passing vector to argv and asking to look for command in PATH

		execve = exec + vector + environment

	}
